2. مقدمة عن النظام

Billora نظام محاسبي وإداري للشركات الصغيرة والمتوسطة. يجمع بين المبيعات، المشتريات، المخزون، الخزينة، دليل الحسابات، والقيود اليومية في تطبيق ويب واحد باللغة العربية.

أبرز ما يقدمه النظام:

  • إدارة العملاء والموردين مع أرصدة مدينة ودائنة.
  • فواتير مبيعات ومشتريات مع تأكيد وترحيل محاسبي وطباعة.
  • مرتجعات مبيعات ومشتريات مع إعادة ضبط المخزون والأرصدة.
  • حركة مخزون يدوية وتنبيه حد أدنى للكمية.
  • خزائن نقدية وبنكية: تحصيل، صرف، وتحويل.
  • مصروفات وإيرادات بتصنيفات مرتبطة بالحسابات.
  • قيود يومية متوازنة (مدين = دائن) ودفتر أستاذ.
  • تقارير تشغيلية ومالية ولوحة مؤشرات.
  • أدوار وصلاحيات، وسجل نشاط، وملف شخصي.
  • تحقق ثنائي عبر رمز OTP يُرسل إلى البريد بعد تسجيل الدخول.

3. المتطلبات والتشغيل

3.1 المتطلبات

  • PHP 8.2 أو أحدث مع إضافات Laravel المعتادة.
  • Composer.
  • خادم ويب مثل Apache في XAMPP.
  • قاعدة بيانات MySQL أو MariaDB (أو SQLite للتطوير).
  • إعداد البريد في ملف .env حتى يصل رمز التحقق.

3.2 عنوان التشغيل المحلي

بعد تشغيل Apache وMySQL من XAMPP افتح:
http://localhost/OTP_tra/public/
إن كان المستخدم مسجلاً يُحوَّل إلى لوحة التحكم، وإلا إلى صفحة تسجيل الدخول.

3.3 أوامر الإعداد الأساسية

  1. نسخ ملف البيئة: copy .env.example .env
  2. توليد المفتاح: php artisan key:generate
  3. ضبط اتصال قاعدة البيانات في .env
  4. تشغيل الترحيلات والبذور: php artisan migrate --seed

البذور تُنشئ دليل حسابات ابتدائي، خزينة، إعدادات الشركة، صلاحيات المدير، وبيانات تجريبية.

4.2 مبدأ العمل المحاسبي

كل عملية مؤثرة مالياً تُسجَّل داخل معاملة قاعدة بيانات واحدة. الخدمة AccountingService تنشئ قيداً يومياً متوازناً، تحدّث أرصدة الحسابات، وأرصدة الخزينة أو العميل أو المورد، وتسجل حركة مخزون إن لزم، ثم تكتب سطراً في سجل النشاط.

إذا لم يتساوَ مجموع المدين مع مجموع الدائن، يرفض النظام القيد برسالة: «القيد غير متوازن». حسابات الأصول والمصروفات تزيد بالمدين، أما الالتزامات وحقوق الملكية والإيرادات فتزيد بالدائن.

4.3 الترقيم التلقائي

أرقام الفواتير والإيصالات والقيود تُولَّد من إعدادات الشركة عبر بادئات مثل SAL للمبيعات، PUR للمشتريات، REC للتحصيل، PAY للصرف، JRN للقيود.

5. الدخول والأمان

5.1 تسجيل الدخول

  1. افتح رابط النظام ثم صفحة تسجيل الدخول.
  2. أدخل البريد أو اسم المستخدم مع كلمة المرور.
  3. يمكن تفعيل «تذكرني» للإبقاء على الجلسة.

الحساب المعطّل أو الموقوف لا يدخل. بعد 5 محاولات فاشلة يُقيَّد الدخول مؤقتاً (حماية من التخمين).

5.2 التحقق الثنائي (OTP)

إذا كان التحقق مفعّلاً على الحساب يحدث التالي:

  1. بعد نجاح كلمة المرور يُولَّد رمز ويُرسل إلى بريد المستخدم.
  2. يُحوَّل المستخدم إلى صفحة إدخال الرمز ولا يصل للوحة قبل التحقق.
  3. الرمز له صلاحية زمنية. يمكن إعادة الإرسال بعد انتهاء العداد.
  4. ثلاث محاولات خاطئة تقفل التحقق لمدة 5 دقائق.
  5. بعد الرمز الصحيح تُمسح بيانات OTP ويُسجَّل وقت آخر دخول.
تأكد أن إعدادات البريد في .env صحيحة. بدون بريد لن يصل رمز التحقق للحسابات المفعّل عليها OTP.

5.3 تسجيل الخروج والملف الشخصي

من القائمة يمكن فتح الملف الشخصي لتعديل الاسم والبيانات أو تغيير كلمة المرور. تسجيل الخروج ينهي الجلسة ويعيد المستخدم لصفحة الدخول.

7. دليل استخدام الوحدات

7.1 العملاء

المسار: العملاء ← قائمة العملاء

  1. أضف عميلاً: الاسم، الهاتف، والبيانات الأخرى. يُولَّد كود تلقائي إن وُجد التسلسل.
  2. من صفحة العميل يمكن مراجعة فواتيره ورصيده الحالي.
  3. تحصيل من العميل: يحدد المبلغ والخزينة. ينقص رصيد العميل ويزيد رصيد الخزينة ويُنشأ قيد تحصيل.
  4. حسابات العملاء تعرض الأرصدة المدينة مجمّعة.

7.2 الموردون

المسار: الموردون ← قائمة الموردين

  1. أضف مورداً بنفس أسلوب العملاء.
  2. سداد للمورد ينقص رصيد المورد ورصيد الخزينة، مع قيد صرف.
  3. لا يُسمح بالصرف إذا رصيد الخزينة أقل من المبلغ.

7.3 المنتجات والتصنيفات

المسار: المنتجات والمخزون

  1. أنشئ تصنيفاً أولاً إن لزم (مثل: عام، أجهزة، خدمات).
  2. أضف منتجاً: الاسم، SKU، النوع (منتج أو خدمة)، الوحدة، سعر التكلفة، سعر البيع، الحد الأدنى، والمخزون الحالي.
  3. المنتجات من نوع «منتج» تؤثر في المخزون عند البيع والشراء. الخدمات لا تخصم كمية.

7.4 حركة المخزون

المسار: المنتجات والمخزون ← حركات المخزون

  • وارد (in): يزيد الكمية.
  • منصرف (out): ينقص الكمية بعد التأكد من كفايتها.
  • تسوية: ضبط الكمية إلى رقم محدد.

كل حركة تُسجَّل بتاريخها وتكلفتها وملاحظات اختيارية. لوحة التحكم تنبّه عندما تصل الكمية إلى الحد الأدنى أو أقل.

7.5 المبيعات

المسار: المبيعات ← فواتير المبيعات

  1. أنشئ فاتورة: اختر العميل والتاريخ وأضف بنود المنتجات والكميات والأسعار.
  2. يمكن إدخال خصم وضريبة. الحالة الابتدائية: مسودة.
  3. راجع الفاتورة ثم اضغط تأكيد. عند التأكيد:
    • يُخصم المخزون للمنتجات السلعية إن كانت الكمية كافية.
    • يُرحَّل قيد: مدين العملاء / دائن المبيعات (مع الضريبة والخصم وتكلفة البضاعة إن وُجدت).
    • يزيد رصيد العميل بالمتبقي.
  4. من الفاتورة يمكن تحصيل مبلغ كلي أو جزئي، أو إلغاء المسودة، أو طباعة.
  5. الحالات: مسودة، مؤكدة، مدفوعة جزئياً، مدفوعة، ملغاة.

7.6 مرتجعات المبيعات

  1. أنشئ مرتجعاً مرتبطاً بالعميل وبنود الإرجاع.
  2. عند التأكيد تُعاد الكميات للمخزون، ويُخفض رصيد العميل، ويُنشأ قيد عكسي على المبيعات والعملاء.

7.7 المشتريات ومرتجعاتها

نفس أسلوب المبيعات مع عكس الأطراف:

  • تأكيد فاتورة مشتريات يزيد المخزون ويزيد رصيد المورد، ويقيد المخزون مديناً والموردين دائنين.
  • السداد من صفحة الفاتورة أو من المورد ينقص المتبقي ورصيد المورد والخزينة.
  • مرتجع المشتريات يخصم من المخزون ويخفض التزام المورد. يرفض النظام المرتجع إن لم تكف الكمية.

7.8 الحسابات والقيود

المسار: الحسابات

  • دليل الحسابات: شجرة بحسابات أصول، التزامات، حقوق ملكية، إيرادات، مصروفات. الحسابات النظامية جاهزة من البذور.
  • القيود المحاسبية: يمكن إنشاء قيد يدوي بعدة أسطر مدين/دائن. لن يُحفظ إن لم يتوازن.
  • الحسابات المدينة / الدائنة: متابعة العملاء والموردين.
  • دفتر الأستاذ: من التقارير، اختر حساباً لعرض حركة مدين ودائن.

7.9 الخزينة

المسار: الخزينة

  1. أضف خزينة نقدية أو بنكية واربطها بحساب في الدليل.
  2. تحصيل: دخول نقدية (من عميل أو عام) تزيد رصيد الخزينة.
  3. صرف: خروج نقدية (لمورد أو عام) بشرط كفاية الرصيد.
  4. تحويل: نقل مبلغ من خزينة إلى أخرى مع قيد بين حسابيهما إن كانا مربوطين.

البذور تنشئ «الخزينة الرئيسية» برصيد افتتاحي 10,000 ج.م و«الحساب البنكي» برصيد صفر.

7.10 المصروفات والإيرادات

  1. أنشئ تصنيفاً (مثل إيجار أو إيرادات متنوعة) واربطه بحساب مصروف أو إيراد.
  2. سجّل عملية: النوع، التصنيف، الخزينة، المبلغ، التاريخ، والوصف.
  3. المصروف ينقص الخزينة ويجعل المصروف مديناً. الإيراد يزيد الخزينة ويجعل الإيراد دائناً.

8. دورة الفاتورة من المسودة حتى السداد

مثال عملي لمبيعات منتج تجريبي لعميل تجريبي:

  1. تأكد من وجود منتج بمخزون كافٍ وسعر بيع.
  2. أنشئ فاتورة مبيعات للعميل وأضف البند. الحالة: مسودة (لا قيد ولا خصم مخزون بعد).
  3. أكد الفاتورة: ينقص المخزون، يزيد رصيد العميل، ويظهر قيد يومية برقم بادئة JRN.
  4. حصّل من الفاتورة أو من صفحة العميل واختر الخزينة. المتبقي ينقص حتى تصبح الحالة «مدفوعة».
  5. إن رجع العميل بضاعة: أنشئ مرتجع مبيعات وأكّده لإعادة الكمية وتخفيض الرصيد.
المسودة قابلة للإلغاء دون أثر محاسبي. بعد التأكيد تصبح العملية مرحلة ولا يُعاد تأكيدها.

11. التقارير والإعدادات

11.1 التقارير المتاحة

  • تقرير المبيعات / المشتريات حسب فترة من–إلى.
  • تقرير المخزون وقيمته وتنبيه الكمية المنخفضة.
  • تقرير أرصدة العملاء والموردين.
  • تقرير المصروفات والإيرادات.
  • الأرباح والخسائر للفترة المختارة.
  • التقارير المالية حسب أنواع الحسابات.
  • دفتر الأستاذ لحساب محدد.

11.2 الإعدادات

من الإعدادات تُحدَّث بيانات الشركة، العملة ورمزها، اللغة، بادئات الترقيم، والحسابات الافتراضية للترحيل. غيّر هذه الربط بحذر لأن القيود الجديدة تعتمد عليه.

13. ملخص سريع للاستخدام اليومي

  1. سجّل الدخول وأدخل رمز البريد إن طُلب.
  2. راجع لوحة التحكم والمخزون المنخفض.
  3. أضف أو حدّث العملاء والموردين والمنتجات.
  4. أنشئ فواتير مبيعات/مشتريات كمسودة ثم أكّدها بعد المراجعة.
  5. حصّل من العملاء وادفع للموردين من الخزينة المناسبة.
  6. سجّل المصروفات اليومية (إيجار، تشغيل، وغيرها).
  7. راجع القيود والتقارير في نهاية اليوم أو الشهر.
  8. اطبع الفواتير عند الحاجة من زر الطباعة داخل الفاتورة.
